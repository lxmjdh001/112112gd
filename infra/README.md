# D1 Scrm 服务器发布

发布包包含 Linux 静态 Go API、网站静态文件、systemd / Caddy 配置、备份脚本及 SHA-256 清单，不包含数据库和真实凭据。客户端需另行使用正式服务地址构建。

## 构建

源码提交后，在仓库根目录执行（PATH 中需要 Node、pnpm、Go）：

```sh
bash scripts/package-server.sh
# ARM Linux：D1_GOARCH=arm64 bash scripts/package-server.sh
```

产物位于开发镜像 `.runtime/releases/<提交>-linux-<架构>.tar.gz`，不会覆盖本机 API 或客户端。解压后在目录内执行 `sha256sum -c SHA256SUMS`。

## 首次安装与切换顺序

以下为操作顺序，执行前先确认服务器架构、磁盘、现有 PostgreSQL、Caddy 路由及实际运行服务。

1. 核对旧部署。历史记录是 `187.77.129.250`、`scrm.chuhai7.com`、`/opt/scrm-web/current`，旧服务 `scrm-web` 和 `omnichat`。配置和其他域名可能已变动，必须读取现状。不要停止整台服务器或覆盖共享 Caddyfile。
2. 备份旧程序、systemd / Caddy 配置、环境密钥、SQLite 和媒体 / 会话目录。运行中的 SQLite 使用 `.backup` / 在线备份 API 获得一致快照；需要整体复制时短暂停止对应写入服务。确认备份完整、记录服务启用状态后再切换。旧副本保留到用户确认可以清理。
3. 本次首次部署使用独立的新生产数据库，旧版和本机数据不自动导入。后续如需迁移，先确定数据来源并备份；旧版 SQLite 不能直接导入新版 PostgreSQL。
4. 安装 PostgreSQL（已有实例则复用并新建独立角色 / 数据库），创建系统用户 `d1scrm`；创建同名 PostgreSQL 非超级用户和同名数据库，数据库由该角色拥有。只允许本机 Unix socket / 回环访问。环境示例通过系统用户 `d1scrm` 的 peer 认证连接。
5. 发布到 `/opt/d1scrm/releases/<版本>/`，程序和静态文件由 root 拥有，目录可读可遍历、API 可执行；`/opt/d1scrm/current` 指向该版本。密钥不能放在 `web/`。检查 Caddy 用户可读取静态文件。
6. 将 `api.env.example` 复制到 `/etc/d1scrm/api.env`（root / 0600），设置独立的 32 字节随机主密钥、随机管理员密码、正式 HTTPS 地址。禁止复用示例值，凭据交付到用户受保护的本地文件。迁移加密数据必须同时迁移匹配的主密钥。
7. 安装 `d1-api.service`，执行 `systemctl daemon-reload` 和 `systemctl enable --now d1-api`。启动时执行 001–020 事务迁移。验证本机 `/healthz`、后台登录、注册、登录码、多设备权限和计费。验证管理员后可移除环境中的两项 `BOOTSTRAP_*`，账号已保存在数据库。
8. 备份并修改现有站点 Caddy 路由，`/api/*` 和 `/healthz` 转发至 `127.0.0.1:18080`，静态文件指向新版 `web/`。Caddy 必须覆盖 `X-Real-IP`，不能透传访客伪造的值。Go 仅信任回环代理提供的该头；如果经过 CDN，需按现场配置核验真实地址来源。
9. `caddy validate` 成功后平滑 reload，验证公网 HTTPS 首页、登录、注册、API 和静态资源。CDN 如使用 HTTP 回源，保留经核验的原有代理路由，避免重定向循环。旧 `/web-api` / 下载入口明确停用，不继续分发旧客户端。
10. 新站验证通过后，停止并禁用已确认属于旧版的服务及账号容器 / 定时器，保留数据；不能停止不相关的 Docker 容器、网站和服务。公网验证失败则还原 Caddy 配置 / 旧服务状态。
11. 安装 `d1-backup.sh` 为 `/usr/local/sbin/d1-backup`（root / 0700）和备份 service / timer，启用定时器，手动完成首个备份并在独立临时库演练还原。备份在 `/var/backups/d1scrm`（0700），包含数据库和匹配的加密配置，不通过网站提供下载。完成受保护的异机副本后才具备服务器故障恢复能力。

## 升级与回滚

升级先执行 `/usr/local/sbin/d1-backup`，记录旧 current 指向。新版本上线后检查 `/healthz` 和业务接口。迁移在事务中串行执行；跨数据库变更回滚时，核对兼容性或恢复对应数据库快照和密钥，不能只退回二进制。恢复前再次备份现有数据，并确定切换期间新增数据的处理方式。

## 客户端地址

```sh
GONGDAN_API_URL=https://scrm.chuhai7.com pnpm build:desktop
```

构建可以通过 `GONGDAN_DESKTOP_OUTPUT_DIR` 指定独立输出目录，避免覆盖本机开发版本。当前已提供本机线上客户端入口，见 `docs/服务器发布状态.md`。这不代表已生成正式签名安装包；普通开发命令默认仍连接 `127.0.0.1:18080`。

## 同码多电脑

同一个有效登录码可在不同安装实例同时登录，各自持有设备会话；登录、退出某台设备不会撤销其他设备。停用 / 重置登录码或欠费强制退出仍按授权规则生效。

- 共享：同登录码的个人话术 / 图片、团队话术 / 图片、客户标签、同团队同平台同客户的资料 / 备注 / 客户语言，以及已分配的 WhatsApp API 会话。界面通过读取 / 刷新获取服务器更新，并非全部模块实时推送。
- 普通扫码号位仍绑定电脑；在其他设备显示不可用，不能直接打开。浏览器 Cookie、平台登录会话及本机消息数据不会复制到另一台电脑。跨设备使用需解绑 / 重新授权，或者另行开发跨设备会话机制。
- 扣点按公司、平台和实际账号标识的北京时间自然日去重，不按客户端登录数量计费。
