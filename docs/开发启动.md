# 本机启动与验证

当前交付为 0.1.0 基础开发版。管理网站采用 Vben Element Plus，服务端 Go + Gin + PostgreSQL，桌面客户端采用 Electron。WhatsApp 聊天窗口是官方网页，翻译是独立的小浮层。

## 本机路径

| 用途 | 路径 |
| --- | --- |
| 主源码及 Git 仓库 | `/Volumes/Lexar/web/gongdan007` |
| 本机依赖、构建与运行镜像 | `/Users/chaoteng/Projects/gongdan007-dev` |
| 数据库、加密密钥与开发环境配置 | `/Users/chaoteng/.local/share/gongdan007` |
| 本机后台登录信息 | `/Users/chaoteng/.local/share/gongdan007/admin-access.txt` |

Lexar 为 ExFAT，依赖工作区放在本机磁盘。修改主源码后运行 `scripts/sync-dev.sh` 单向同步到开发镜像；不要在镜像里长期维护另一套源码。同步保留镜像中的依赖、构建文件和 `.runtime` 测试输出。

## 启动

分别在三个终端执行：

```sh
cd /Volumes/Lexar/web/gongdan007
sh scripts/dev.sh api
```

```sh
cd /Volumes/Lexar/web/gongdan007
sh scripts/dev.sh admin
```

```sh
cd /Volumes/Lexar/web/gongdan007
sh scripts/dev.sh desktop
```

后台地址为 `http://127.0.0.1:5777`，API 地址为 `http://127.0.0.1:18080`，独立 PostgreSQL 监听 `127.0.0.1:55437`。首次运行生成随机管理员密码与代理加密密钥，不内置通用初始密码。再次运行不会覆盖管理员密码。

本机已使用 Node 24.19.0、pnpm 10.28.0、Go 1.25.3、PostgreSQL 17.7、Electron 44.7.0 验证。启动脚本优先使用本机现有 Node 24。其他环境需准备 Vben 支持的 Node 22.18+ 或 24，以及 Go 1.25+、PostgreSQL。`GONGDAN_PG_BIN`、`GONGDAN_LOCAL_DATA`、`GONGDAN_DEV_DIR` 可覆盖本机路径。

## 实际使用顺序

1. 管理员登录网站，创建长期登录码，设置有效期、设备额度和账号额度。完整码只在生成、重置时显示一次。
2. 在代理管理中逐行粘贴真实代理，导入成功后，在账号列表创建账号位，选择所属登录码与代理。
3. 员工启动客户端输入登录码，点击左侧账号，在 WhatsApp 官方页面上用手机扫码。
4. 选中聊天文字后点击“译 · 翻译”，也可以右键翻译。输入回复、选择目标语言后查看译文，复制到 WhatsApp，由员工自行发送。
5. 管理员可以停用、重置登录码或解绑设备。重置使旧码和旧客户端会话失效；解绑释放设备额度，仍持有有效码的人可以再次登录，禁止重登应同时重置或停用登录码。

连接真实平台必须使用自己的代理。自动化验收用的是临时本机代理，只用来验证代理路由及认证，不提供独立公网出口。

## 验证命令

在开发镜像中执行：

```sh
pnpm typecheck:admin
pnpm --filter @gongdan/desktop typecheck
pnpm test:desktop
pnpm build:admin
pnpm build:desktop
cd server
TEST_DATABASE_URL='postgres://127.0.0.1:55437/gongdan007?sslmode=disable' go test ./...
```

完整界面验收：

```sh
cd /Volumes/Lexar/web/gongdan007
sh scripts/dev.sh check
```

验收启动临时 API `18081`、网站预览 `5779`，创建独立数据库 schema，结束后关闭服务并删除该 schema。需要 Chromium：首次可以在开发镜像运行 `pnpm exec playwright install chromium`。Electron 测试会显示临时客户端窗口、加载官方登录页、用测试文字访问 Google；不会关联手机账号或发送 WhatsApp 消息。截图保存在开发镜像 `.runtime`，不纳入 Git。

## 发布边界

当前服务仅在本机启动，没有覆盖旧网站，也未部署到生产服务器。客户端目前通过开发命令运行；Windows / macOS 安装包、签名、自动更新、线上 TLS、生产数据库权限、运维监控与恢复演练属于后续发布阶段。

数据库不是 Git 的一部分。代理加密密钥必须随受保护的数据库备份单独保管，否则备份中的代理密码无法解密。源码仓库当前尚未配置远程地址。
