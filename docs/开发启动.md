# 本机启动与验证

当前交付为 0.1.0 基础开发版。管理网站采用 Vben Element Plus，服务端 Go + Gin + PostgreSQL，桌面客户端采用 Electron。WhatsApp 聊天窗口是官方网页，翻译是独立的小浮层。

Lexar 为 ExFAT，依赖工作区放在本机磁盘。修改主源码后运行 `scripts/sync-dev.sh` 单向同步到开发镜像；不要在镜像里长期维护另一套源码。同步保留镜像中的依赖、构建文件和 `.runtime` 测试输出。

该文件系统产生的 AppleDouble `._*.idx` 会干扰 Git 维护，因此源码目录里的 `.git` 为指向上述本机元数据目录的标准 Git 文件。所有正常 Git 操作仍在主源码目录执行。迁移到其他电脑时使用 Git bundle 恢复，不要仅复制这个 `.git` 指针。迁移前的原始元数据额外保存在 `/Volumes/Lexar/web/.gongdan007-git-preserved-20261009-854a137`。

## 实际使用顺序

1. 管理员登录网站，创建长期登录码，勾选客户端可用平台，再设置有效期和分组；登录码不限制设备数或账号数。完整码可在生成 / 重置后复制，也可随时在列表登录码旁点击“复制”。旧版未保存完整码的记录可先补存原码，或等待使用者下次用原码登录客户端自动补存；不会自动重置登录码。
2. 如需独立 IP，管理员可在网站“代理管理”中导入代理并设置分组、每平台账号上限和启用状态；使用当前电脑网络无需添加代理。后台账号列表没有创建入口。
3. 使用者启动客户端输入登录码，点击左侧“添加账号”，先在弹窗中选择“使用当前电脑网络（默认）”或“设置独立 IP”，再填写名称和已授权平台；独立 IP 模式还需选择代理。点击“添加并登录”，在 WhatsApp 官方页面扫码。账号自动绑定当前登录码和设备，并同步到后台账号列表；已有账号直接从左侧打开。
4. 选中聊天文字后点击“译 · 翻译”，也可以右键翻译。输入回复、选择目标语言后查看译文，复制到 WhatsApp，由使用者自行发送。
5. 管理员可以停用、重置、单条或批量删除登录码，也可以解绑设备。重置使旧码和旧客户端会话失效；解绑撤销该设备授权，仍持有有效码的人可以再次登录，禁止重登应同时重置或停用登录码。

默认模式沿用当前电脑的网络设置，账号和翻译通过同一个独立会话联网。需要固定独立出口时选择自己配置的代理 IP，继续执行单 IP、单平台上限。自动化验收的临时本机代理只用于验证路由及认证，不提供独立公网出口。

## 客户端平台授权

在创建登录码时勾选“客户端可用平台”，至少选择一个已开放的平台。当前 WhatsApp 可用，LINE 待开放。登录码列表展示授权平台，点击“编辑”可调整；取消全部平台后，客户端不能添加或打开平台账号。已有登录码升级后保留 WhatsApp 权限。

客户端左侧显示当前可用平台。权限变化会在正常心跳或点击刷新时同步；取消某个平台会关闭对应已打开的网页，保留本机登录资料。重新授权后点击原账号打开。平台账号依然在客户端添加和登录，无需管理员创建账号位；若仍显示“等待管理员分配账号”，请关闭旧客户端后重新运行 `sh scripts/dev.sh desktop`。

## 登录码分组

在“登录码列表”点击“管理分组”可创建、重命名或删除分组；创建登录码的弹窗也提供分组选择和新建入口。列表左上角可选择全部分组、未分组或具体分组，表格支持勾选后批量移动。删除分组保留原登录码及已登录客户端。

服务升级时自动应用迁移 002，已有登录码默认归入未分组。

## 代理管理

“添加 / 批量导入”支持每行一个代理，本次导入统一应用所选分组、每平台上限和启用状态。每平台上限默认 1，待扫码及离线账号也占额度；不同平台独立计算。列表“设置”可修改这些项目，勾选后支持批量移组、启用、禁用。

“管理分组”支持创建、重命名和删除；删除后原代理归入未分组。已有代理升级保留分组和关联账号，上限不低于已有数量。

禁用代理会阻止添加 / 打开账号，新版客户端在下一次同步（正常约 30 秒）暂停已打开的相关账号，保留登录资料。重新启用后点击原账号继续使用。本轮已运行的旧版客户端需要重新启动。

## 账户中心与推广中心

“账户中心”可维护资料、改密码、提交充值申请并查询账务记录；“推广中心”提供专属推广链接、推广客户、佣金、转余额及提现。网站账户与客户端登录码独立，注册的新团队通过网站再创建自己的登录码。

当前启动配置中的管理员可见“账户中心 → 运营管理”。先在“结算规则”设置实际币种、收款说明、佣金比例和提现渠道，再按需开放充值、提现及注册。初始状态均关闭，没有自动接入任何收款账户。测试中的金额和比例只存在于临时测试库。

充值操作流程：客户先按说明付款并提交申请 → 运营核对实际到账及金额 → 填写唯一实收流水号确认 → 余额与推广佣金同时记账。系统不会因提交申请直接增加余额。

提现操作流程：客户申请并冻结佣金 → 运营审核 → 运营在线下完成打款 → 登记唯一打款流水号。拒绝或取消会解冻；通过审核不等于已打款。当前仅支持人工登记，不会自动调用支付服务。整单退款需录入退款流水，且相关余额 / 佣金可完整冲回。

字符日志需要重启新版客户端后开始上报，只记录字符数量，不保存聊天内容，免费翻译不扣余额。暂无已定价套餐，购买记录保持真实空状态。

## 客户端保持登录

新版客户端会记住登录状态，关闭窗口后重新打开也无需重复输入登录码。管理服务短暂不可达时显示自动重连提示，已打开的聊天页面继续保留。点击“退出客户端”才清除本机客户端登录；后台停用 / 重置 / 到期或解绑设备仍会撤销授权。升级前旧版已经清除的凭证无法恢复，需要再输入一次登录码。WhatsApp 官方页面的扫码授权由平台独立管理。


### 固定 IP 上限与客户端服务地址（2026-10-10）

代理设置中的“每平台最多登录”表示单个固定 IP、单个平台的账号数量。设为 1 时，不同平台分别占 1 个名额，同平台的第二个账号会被拦截。相同 IP 的不同端口、协议、用户名以及不同登录码、设备共享计数；待扫码、离线、所属登录码已删除的账号也保留占用。修改上限会同步同 IP 的记录，重复导入沿用该 IP 原有上限。

目前按配置中的固定 IP / 规范化主机名识别；不自动检测不同网关地址背后的相同出口，也不用于动态轮换出口代理。旧库已有账号保留，迁移时上限不会低于现有同平台占用数。

使用者登录页只填写登录码。开发环境默认后台为 `http://127.0.0.1:18080`，测试环境在独立进程通过 `GONGDAN_API_URL` 指定地址并使用隔离数据目录、隐藏窗口。打包时由发布者设置 `GONGDAN_API_URL=https://实际后台域名 pnpm build:desktop`，正式客户端不从登录表单读取服务地址；缓存会话只在服务器地址相同时恢复，防止将旧凭据发送给另一个服务。


## WhatsApp API 接入与验证

入口：`http://127.0.0.1:5777/#/whatsapp-api`。本机可以查看模块；真正接收 Meta Webhook 必须部署可从公网访问的 HTTPS 服务，反向代理保留 POST 原始请求体及 `X-Hub-Signature-256` 请求头。

1. 在服务端环境设置 `GONGDAN_PUBLIC_URL=https://你的后台域名`（仅源地址，不带子路径），重启 API。`WHATSAPP_GRAPH_VERSION` 默认固定为 `v25.0`，升级前验证兼容性。
2. 在 Meta 完成业务号码注册，准备 App ID、App Secret、Phone Number ID、WABA ID，以及具备 `whatsapp_business_messaging` / `whatsapp_business_management` 权限且获授对应 WABA 资产的系统用户访问令牌。资料只填到本系统号码添加表单，不写入源码或 Git。
3. 「WhatsApp API → 添加 API 号码」验证资料，随后打开「回调配置」。复制回调地址和校验串到对应 Meta 应用的 WhatsApp Webhook 配置，订阅 `messages`。回到号码列表点击「订阅消息」完成该 WABA 对应用的订阅。
4. 创建 / 编辑登录码，勾选「WhatsApp API」，在号码的「分配」中选择登录码。使用者登录客户端后点击该号码，即可进入 API 聊天；网站也可从「在线聊天」处理。
5. 「同步模板」读取 WABA 已有模板。新客户 / 超过客服窗口用获批文本模板发起；客户回消息后，24 小时内可发普通消息及附件。翻译先预览，应用到草稿后仍需手动发送。

系统不会替你生成 Meta 永久有效的令牌；令牌也可能被撤销或失效，可在编辑号码中更新。API 无原生 WhatsApp Web 页面，使用单独的聊天视图；普通扫码入口继续使用官方网页。客户的公网 IP 不在 Cloud API 回调中，底库手机号 / 账号查重正常生效。
