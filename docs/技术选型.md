# gongdan007 技术选型

最终方案为 Vue Vben Admin 的 Element Plus 版本、Go 网站后端、Electron 原生网页客户端。选型核对日期为 2026 年 10 月 9 日。

## 中后台

选择 Vue Vben Admin。官方提供 Element Plus 版本，具备动态菜单、路由权限、主题和 TypeScript 工程组织，适合本项目的大量表格与管理页面。它提供的是中后台前端基础，登录码、租户数据权限、财务与客户运营由 Go 业务服务实现。[官方介绍](https://doc.vben.pro/guide/introduction/vben.html)

基础版本候选为 `v5.7.0`，其 `apps/web-ele` 为 Element Plus 应用，许可证为 MIT。引入时保留所需共享包和许可证，业务放在独立模块中。上游采用 monorepo，不能只复制 `apps/web-ele` 后忽略它依赖的共享包。[固定版本](https://github.com/vbenjs/vue-vben-admin/releases/tag/v5.7.0)、[对应许可证](https://github.com/vbenjs/vue-vben-admin/blob/v5.7.0/LICENSE)

用户已明确排除 Ant Design Pro；组件库使用 Element Plus。gin-vue-admin 曾作为候选，核对发现 `v2.9.2-stable` 标签的许可证文件为 BSL 1.1，而当前主分支为 Apache 2.0，选型依据不能混用两个版本。本项目选择有明确固定版本依据的 Vben 方案。[稳定标签文件](https://github.com/flipped-aurora/gin-vue-admin/blob/v2.9.2-stable/LICENSE)、[主分支文件](https://github.com/flipped-aurora/gin-vue-admin/blob/main/LICENSE)

## 服务端

采用 Go 与 Gin，PostgreSQL 作为业务主库。用户选择 Go 的意图落实在业务后端；业务功能按领域组织，以公开接口交互。使用成熟的路由、数据库和权限组件，但领域模型、登录码和设备名额由本项目明确设计。

GORM 处理常规数据访问，显式 SQL 迁移处理建表与升级；并发名额、账本事务和事件去重以数据库约束保证。初版可用 PostgreSQL 任务表承担可靠后台任务，后续根据监控再引入专用队列或缓存。

## 客户端

采用 Electron，以 Chromium WebContentsView 直接承载官方平台网页。其 Session API 可以提供独立持久化浏览器会话及会话代理。上述接口是实现基础，平台兼容性和网络隔离必须通过测试验证。[WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view)、[Session](https://www.electronjs.org/docs/latest/api/session)

原生网页要求使客户端重点变成浏览器会话管理。Go 与 Wails 的自绘聊天方案不作为此次开发基线；也不以 whatsmeow 或 Baileys 另建一套协议会话来替代官方网页。

最初候选为 Vue 3 外壳；0.1.0 实际使用轻量 TypeScript + DOM 外壳，平台网页维持原生 UI。Electron 自带所需运行环境，客户只安装客户端。多个官方网页会增加本机内存占用，需要实测并提供账号暂停机制。

## 版本基线

| 项目 | 规划基线 | 引入规则 |
| --- | --- | --- |
| Vben | `v5.7.0` | 以固定 tag 和解析后的 commit 引入 |
| Vben 组件方案 | `apps/web-ele` | 只启用 Element Plus 业务应用，保留必要 workspace 依赖 |
| 前端构建环境 | Node.js 24 系列与 pnpm 10 系列 | 与 Vben 的 engines 一致，实际补丁版本写入工具链配置 |
| Electron | 当前稳定版本候选 `v44.7.0` | P1 实测后锁定版本，持续更新安全补丁 |
| Go | 本次使用 `go1.25.3`，模块最低 `1.25.0` | `go1.27.2` 为规划时的新版本候选，尚未切换构建环境 |
| PostgreSQL | 受支持的稳定主版本 | P2 选定并锁定镜像版本，演练备份与恢复 |

候选版本不是已安装版本。依赖正式引入时提交 lockfile、上游 commit 和必要 NOTICE，数据库及运行目录不进入代码仓库。

## 核心验证点

最先验证官方 WhatsApp Web 在目标客户端中的扫码、重新启动、持续连接、代理、媒体访问和状态识别。能加载官方网页，不自动代表其内部数据可以稳定同步到网站。对聊天归档和监控能力单独给出支持范围、缺口与回归用例。

普通 Session 分区不提供独立物理设备或完整操作系统沙箱。强制网络出口隔离需要针对各操作系统测试并补齐相应的进程与网络控制；产品说明必须与实际达到的隔离级别一致。
