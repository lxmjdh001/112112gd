## 客户端添加账号

平台账号的添加入口只在客户端。网站管理登录码、额度和代理，账号列表展示客户端添加的账号及其状态。移除原 `POST /api/v1/platform-accounts` 后台预分配接口。

客户端先请求可用平台、当前登录码额度和本团队启用的代理摘要，再添加账号。服务端从客户端会话确定租户、登录码与设备，不接受调用方指定归属；账号一经添加就绑定当前设备。按登录码加事务锁控制并发额度，创建请求键确保超时重试不重复占用名额。迁移 003 为旧账号保留原 ID、代理与已有绑定，不清除客户端会话。

添加弹窗打开时暂时隐藏当前官方网页，取消后恢复，保留原生页面和 Cookie。添加成功后进入官方扫码页；网络失败时账号仍保留，可从侧栏重试。添加成功不等于 WhatsApp 登录成功。

## 登录码的平台授权

创建登录码必须明确勾选至少一个已开放的平台；当前可选 WhatsApp，LINE 显示为待开放，服务端拒绝伪造未接入平台的授权。列表显示可用平台，“编辑”可调整名称、有效期、额度和平台权限。编辑时可取消全部平台，登录码本身仍有效，客户端显示未分配平台；账号仍由使用者在客户端添加和登录，后台不预创建平台账号。

迁移 `007_code_platforms.sql` 为已有登录码保留 WhatsApp 权限。重置码值不改变平台权限；旧编辑请求省略 `allowedPlatforms` 时保留现有授权，不能隐式恢复已撤销的平台。新增创建请求必须提供非空 `allowedPlatforms`；API 与前端均拒绝未开放、未知和重复的平台选项。

客户端展示登录码可用平台，只在被授权的平台中选择。服务端同时校验账号添加（包含重试）、打开、状态上报、翻译数量上报和客户查重 / 登记。创建与平台权限编辑按登录码行加锁，打开账号先读取受锁保护的最新权限。取消授权后，运行中的相应原生页面在下次同步（正常约 30 秒）关闭，管理服务失联期间保留页面直到重新联网校验；保留本机 Cookie、账号 ID 与关联代理。恢复授权后可重新打开原账号。

已验证创建必选、编辑后刷新保持、撤销 / 恢复、跨团队拒绝、重置保留授权、旧库迁移，以及 Electron 心跳暂停原生页面、恢复后继续使用同一持久化分区。已运行的旧客户端需重启加载此版本。

## 登录码分组

分组属于当前团队。同一团队不能创建同名分组，名称前后空白会去除，最长 50 个字符。“未分组”是默认分类，不创建独立分组记录。

创建登录码可直接选择分组；列表显示所属分组与每组数量，筛选可与名称 / 尾号搜索组合使用。既有登录码可单个调整或勾选批量移动，每次最多 500 个。删除分组只把其中登录码归入未分组，不修改码值、有效期、设备额度、账号绑定或客户端会话。

新增数据库迁移 `002_login_code_groups.sql`，启动时在事务中升级；既有登录码保留并默认未分组。管理接口均校验租户，跨团队混合批量请求整批拒绝；数据库外键也限制跨团队关联。迁移可重复运行。

## 代理分组、额度与启用状态

每条代理记录设置统一的每平台账号上限，默认 1，可设 1–10000。同一平台按已关联账号数计数，包括未扫码、离线账号；不同平台独立计数。客户端选项显示已用 / 上限，满额代理不可选；服务端按登录码、代理顺序加事务锁，即使不同登录码并发创建也不能突破代理额度。调低上限时不能小于当前任一平台已有账号数。

代理分组与登录码分组独立，支持创建、重命名、删除、筛选、导入时选组、单个设置与批量移动。删除分组只归入未分组。启用状态可在导入时设置，或逐个 / 批量更改；批量接口对租户和成员完整性校验，混入其他团队代理时整批拒绝。

禁用后服务端立即拒绝新增关联和打开账号，已打开页面在客户端下次同步（正常心跳间隔 30 秒）关闭并阻断连接，客户端显示“代理已禁用”，保留原 ID、绑定、代理凭据与本地 Cookie。重新启用后手动打开原账号；管理服务失联时保留客户端登录和已打开页面，恢复连接后同步最新权限并执行撤销。

迁移 `004_proxy_controls.sql` 保留旧分组名并生成对应分组；若已有代理关联多个同平台账号，其初始上限自动提升到现有最大数量，避免升级阻断原账号。该限制按代理记录计数，尚未实现跨批次重复代理资产合并或基于真实出口 IP 聚合额度。

## 账户中心与推广业务

迁移 `005_account_promotion.sql` 增加个人资料、运营权限、结算规则、两类钱包、不可覆盖的流水、充值单、推广关系、佣金、转余额、提现单与用量记录。既有管理员资料和会话保留。由启动配置 `BOOTSTRAP_USERNAME` 对应的管理员获得平台运营权限；注册账户只管理自己的团队，不能通过请求参数取得审核权限。

个人资料支持团队名、显示名、联系方式；修改密码校验旧密码，撤销其他网站会话，保留当前会话及客户端登录码。注册默认关闭，运营开启后，推广链接直达注册页并填写独立推广码；只有新注册时绑定归属，不补绑已注册账户，也未加入跨日 Cookie 归因。停用链接阻止新推广注册，已成立的推广关系不变。

充值、提现均为人工审核模式，本系统不向银行或链上服务发起收款 / 转账。新安装默认未设置币种，充值、提现、注册关闭，佣金比例为 0；测试币种 / 10% 比例仅用于隔离测试库，没有写入日常数据库。运营需在“账户中心 → 运营管理 → 结算规则”设置实际币种、说明、比例及门槛。

金额以最小单位整数存储，接口以十进制字符串返回，统一两位小数；单笔上限 1000000.00。产生账务记录后币种不可切换。入账时计算佣金并保存当时比例，按分向下取整，低于 0.01 不生成佣金。申请、余额变动、佣金和审计在数据库事务中提交；请求 UUID、实收流水号和打款流水号用于防止重复入账 / 结算。

佣金与账户余额分开：转余额从佣金扣除并增加账户余额，不再返佣。提现申请将可用佣金转为冻结；取消或拒绝解冻，通过审核仍保持冻结，实际线下打款后登记唯一流水号才扣除冻结并标为已支付。收款信息使用现有 AES-GCM 密钥加密，列表脱敏，运营查看完整信息会记录审计。

退款只支持整单冲正，需填写线下退款流水及原因；账户可用余额与对应可用佣金必须足够，若已消费 / 转出 / 冻结则整笔拒绝，不生成负余额或部分冲正。复杂退款追偿、部分退款和支付渠道对接尚未实现。平台钱包流水与外部支付机构的核对仍由运营执行。

字符日志记录新版客户端实际发起并成功返回的免费翻译请求（缓存命中不重复记数），只含账号、输入 / 输出字符数、目标语言、提供方和时间。不上报原文、译文，不扣余额，失败上报不阻塞翻译。当前是尽力上报，尚无离线持久补传，不用于收费依据。Token 用量未启用，套餐未定价 / 上架，购买记录读取真实空表，无模拟订单或自动扣费。

## 底库与对话查重

迁移 `006_baseline.sql` 新增底库、导入批次和对话查重记录。底库字段为平台、客户平台账号、客户实际公网 IP、来源客服账号（可不指定）、备注与启用状态。账号与 IP 至少填写一项；同一客户可维护多个 IP 证据，不自动把共用 IP 的人合并。平台账号来源可选本团队客户端已添加的客服账号，不能在后台创建客服账号。

查重范围按本次用户确认固定为「同一团队、同一平台、跨全部客服账号」。账号或 IP 任一命中启用底库或在先登记对话即标为重复用户；分别返回账号重复、IP 重复、底库命中与在先对话命中。WhatsApp 手机号规范化并去除 `@s.whatsapp.net` / `@c.us`；`@lid` 保留独立命名空间，无可信映射时不与手机号或同名联系人合并。IPv6 使用规范化地址，IPv4 映射 IPv6 转为 IPv4；拒绝内网、回环、CIDR、端口和 zone 标识。

支持 UTF-8 CSV / TSV / TXT 和粘贴，一行一条，固定三列「客户账号、客户IP、备注」，账号和 IP 可以留空其中一项。最多 1000 行 / 160 KB，先预览并显示新增、重复、错误，再明确确认导入有效行。重复导入不覆盖已有备注、来源和启停状态，导入请求重试返回原批次；无效行可在导入结果下载，批次历史保留行号与原因。只更正备注与启停，账号 / IP 填错时停用旧条目并重新录入，不篡改来源记录。

对话统计单位是「一个客服账号与一个客户账号的首次登记」，同一组合重试不重复计数，不按消息条数、打开聊天次数或日期自动重置。第一条未命中为新用户，另一个客服接待相同客户时为重复用户。网站或客户端由使用者确认实际对话后登记，客户端目前不自动推断新对话。记录保留首次登记时间和当前查重结果；导入、启停不静默改写历史结果，选择平台「重新计算」时使用当前底库及按登记序号在先的对话重算，包括首次登记后的补录底库，更新计算时间而不增加总数。API 写入通过团队 / 平台事务锁及唯一约束避免并发首次客户被多算。

原生 WhatsApp 页面新增独立「客户查重」小浮层，保守读取当前聊天可见消息标识中的直接会话对方 ID，识别成功后自动查重；群聊、混合 PN/LID、未知 DOM 不猜测，不以昵称为 ID。无法识别时手工填写；数据变更或聊天切换会丢弃旧查询结果。后台只收到客户 ID、可选 IP 和归属客服，不接收消息正文、Cookie 或网页授权。WhatsApp 原生页面无法提供客户真实 IP，实际 IP 仅来自用户录入 / 导入或后续接入的数据来源，禁止拿客服代理 IP、客户端请求 IP 替代。LINE 当前支持预先维护底库，不代表已开放 LINE 客户端。

## 翻译行为

当前使用 Google 无密钥网页翻译接口，已实际获得译文。它不是签约的 Google Cloud Translation API，不能承诺免费额度、可用性或长期兼容性。提供者独立封装，后续可接官方 API。

只有使用者主动选中或输入的文字会提交给 Google，经所属账号的代理发送。管理服务不接收消息原文或译文，只接收成功请求的字符数量等用量元数据。每次最多 4000 字符，每账号每分钟最多 20 个未命中缓存的请求，12 秒超时；缓存仅在内存中保留 5 分钟、最多 100 项。错误不会覆盖原文，也不会自动发送。复制后由使用者粘贴并确认发送。

## 授权与状态

网站登录、客户端授权和 WhatsApp 登录是三个独立状态。后台授权失效时关闭原生页面，保留本机平台登录资料；不会为了连接故障清空 Cookie 或重新创建 WhatsApp 登录。

客户端每 30 秒同步授权和账号配置，网络恢复及电脑唤醒时立即重试。管理服务断网、超时、5xx 或客户端重启均保留加密的登录凭证及账号列表，不再因 150 秒超时退出。已打开的原生页面在管理服务失联期间继续保留；重启后先恢复工作台，再向服务器验证并自动打开上次选中的可用账号。新建或打开账号仍需服务端授权与代理配置。

设备会话取消独立的 7 天过期限制，直到主动退出、登录码到期 / 停用 / 重置、设备解绑或同设备重新登录替换凭证。`008_persistent_client_sessions.sql` 只升级当前仍有效且有权限的旧会话，不恢复失效凭证。服务端每次请求继续校验登录码和设备状态；离线期间无法即时接收撤销，重连后执行。关闭窗口不清除登录资料；点击“退出客户端”才清除本机客户端凭证，仍保留平台 Cookie。

网页状态按有限的 DOM 证据分类：加载中、等待扫码、页面就绪、网络异常、待确认。超过 90 秒没有有效观测时网站标为状态过期。“页面就绪”不代表具体消息送达。当前未采集客服账号的真实平台手机号；客户身份仅保守读取当前聊天的可见原生标识，并支持手填，尚待真实已登录账号验收，所以网站账号列表展示的是客户端添加的平台账号，尚不是完整的平台账号资料同步。
