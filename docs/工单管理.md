# 网站工单管理

网站会员登录后打开 `/work-orders`。创建和编辑只允许网站管理员会话，客户端只能为自己绑定的原生账号上报进线元数据。

## 操作

1. 创建工单，填写名称、统计起止时间。
2. 使用现有登录码分组、平台和搜索筛选账号，勾选或全选当前结果。WhatsApp API 号码按其分配的登录码归组；同一个号码只选择一次。
3. 可选目标人数、北京时间每日分界、公司底库去重、分享密码和链接有效期。
4. 保存后复制统计链接。链接无需网站登录，支持密码保护、停用、重置和删除。

账号选择是保存时的快照；分组后续新增账号需要编辑工单加入。删除或停用链接不会删除平台账号及已采集数据。

## 与旧版口径的对应

参考本机恢复的 SCRM 源码 `server/src/campaign-repo.ts` 和 `campaign-stats.ts`：

- 在工单起止时间内取每个 `(平台账号, 客户)` 的第一条入站消息；重复消息及重复上报不加人数。
- 今天、昨天以北京时间及工单配置的每日分界计算，默认 00:00；累计为工单期间。
- WhatsApp 已解析的 LID/手机号映射会合并历史，尚未解析的 LID 按平台标识统计。
- 同平台同一客户进入多个参与账号，各账号各计一次，按首次入站时间排序，后进入的账号标记重复。时间相同时用账号 ID 稳定排序。
- 可选公司当前底库匹配；默认关闭。不以手工添加客户、点击统计链接或打开聊天作为进线依据。
- 已移除账号保留已上报统计，零进线账号仍展示。

本次恢复核心工单/汇总分享流程。旧版广告来源过滤、地区 IP 限制、公开客户明细和独立粉库管理没有迁入。

## 数据与边界

原生账号需要客户端 0.1.3。WhatsApp 读取现有 WAWebCollections 消息模型，Telegram Web K 观察 rootScope 消息事件及已缓存历史加载事件，LINE 3.7.2 观察官方组件 Redux 消息实体。只采集个人收到的消息，排除群聊、出站和系统消息；不主动发送、标已读或抓取全量远程聊天。

统计元数据包括消息 ID、客户标识及原消息时间，不含正文、图片或凭据。主进程验证平台页面、账号身份并加密缓存；网络失败重试，服务器唯一键保证幂等。服务器再次验证租户、登录码、设备绑定和账号身份。

WhatsApp API 使用现有验签回调入库的真实消息，可统计其已保存历史。原生平台仅能统计新版客户端已观察并同步的数据；不能保证升级前、远程未加载或平台已清理的历史完整。页面明确显示等待同步/离线及最近同步时间。未同步数据不会伪造补数。平台官方页面升级可能需要适配，采集器未就绪时显示等待同步。

未获得真实业务平台账号配合验收：已验证平台状态模型夹具、持久队列、真实 HTTP 数据通路及页面流程；真实 WhatsApp / Telegram / LINE 新消息仍应进行业务账号联调。

## 验证

- PostgreSQL 集成测试覆盖日期分界、迟到消息、重复、零账号、移除历史、Cloud 回调、登录码分组、公司/设备权限、分享密码/重置/停用/过期。
- 桌面测试覆盖三个平台元数据观察器、群聊与出站排除、账号切换、断网/重启补报和并发入队。
- `node scripts/run-e2e.mjs --work-orders-only` 检查网站创建、分组批量勾选、公开密码页、统计展示、手机布局和停用；另用 Electron 真实沙箱加载受控 WhatsApp 消息模型，验证元数据经主进程加密缓存、鉴权上传至统计接口的完整链路，不发送真实平台消息。
- 数据库新增迁移 021，不修改既有账号、登录码、余额或计费规则。
