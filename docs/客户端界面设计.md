# D1 Scrm 客户端界面

## 使用场景

面向跨境客服与销售的日常沟通工作台。账号、官方聊天页面、客户资料始终处于同一工作空间。
本次只调整 renderer 的样式、展示结构和可访问性标记，沿用原有账号授权、会话、代理、翻译和客户工具逻辑。

## 设计方案

- 配色：画布 `#F6F7FA`、面板 `#FFFFFF`、正文 `#202939`、辅助文字 `#626C80`、分隔线 `#E3E7EF`、品牌蓝 `#3659D9`。状态色独立定义，平台品牌图标保留官方配色。
- 字体：macOS 使用系统字体和苹方，Windows 使用 Segoe UI / 微软雅黑；不依赖在线字体。正文 13–14px，辅助文字 12px，分区标题 14px，主标题 22px。
- 布局：沿用原生聊天视图的尺寸契约。顶部 58px；左侧展开 280px、折叠 76px；右侧展开 330px、折叠 42px。导航与表单左对齐，初次使用引导在会话区域居中。
- 层级：账号列表、聊天区、客户工具各自形成连续区域。工具通过标题、留白和分隔线组织；弹窗承担独立任务，统一标题、输入框和底部操作。
- 交互：保留全部操作和选择器。统一悬停、按下、禁用、键盘焦点与错误状态。尊重减少动态效果设置。

```text
┌────────────────── 58px：工作台 / 提示 / 操作与点数 ──────────────────┐
│ 280px 账号与平台 │            官方聊天 / 会话引导           │ 330px 客户工具 │
│ 独立滚动        │            尽量保留阅读空间              │ 独立滚动       │
│ 添加 / 刷新     │                                         │ 资料 / 话术    │
└────────────────┴─────────────────────────────────────────┴────────────────┘
```

## 方案复核

UI/UX Pro Max 的 CRM 检索建议采用扁平设计、专业蓝和清晰的交互状态；这些与本项目匹配。
其通用设计系统输出中的营销页结构、在线西文字体不用于客户端。结合 frontend-design，
本次保留系统字体，以连续工作面板取代重复阴影卡片，以真实平台与账号状态表达产品特征。
初始会话引导使用中性的沟通图形，避免多平台工作台默认呈现为单一平台产品。

## 验证范围

构建和类型检查；现有客户端单元测试；模拟账号的原生 / API 会话切换、分组折叠、
退登 / 移除 / 恢复、网络与指纹表单；960px 最小窗口及正常桌面尺寸；两侧面板
折叠组合与原生聊天视图对齐；登录、错误提示、键盘焦点及减少动态效果的截图检查。

## 管理后台的延续

后台采用同一组品牌蓝、灰白画布、正文和辅助文字颜色，沿用 Vben 的语义变量和 Element Plus 的组件变量。
系统字体、8px 控件圆角、12px 面板圆角、表单焦点与状态色保持一致；深色模式提供对应的背景与文字层次。

布局保留既有侧栏、顶部导航、页签及全部业务入口。工作台用连续的四项状态栏和三步操作分区组织真实数据，
列表页统一标题、筛选工具条、表头、行高及空状态，弹窗统一标题、内容和底部操作区。

方案复核后，继续保留后台的数据密度和现有控件，避免把工具页面改成展示页；
UI/UX Pro Max 的 CRM、表格与焦点指导用于组件一致性，frontend-design 用于信息层级、排版与克制的视觉表达。
登录、注册、权限、查询、批量操作、财务和工单逻辑均沿用原实现。
