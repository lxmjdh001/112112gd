# 团队接待与聊天查看

## 使用范围

- 每个客户的后台管理员只查看自己公司的团队；平台超级管理员也不能通过此接口跨公司查看聊天。
- `/leads` 为「新增接待」，`/customers` 为「客户运营」。业务员按登录码识别，同码多设备归在同一业务员下。
- 新增接待按同一平台账号与客户首次收到私聊消息计算；仅发送、未收到回复的客户不计入。不同平台账号分别计数。
- 支持业务员、平台、关键词和北京时间日期筛选。接待日期按首次收到客户消息；客户运营日期按最近对话。
- 共享 API 号码在团队合计中只计一次，业务员筛选会匹配被分配的号码，各业务员小计不能相加作为独立客户合计。

## 聊天同步与历史

- 每个公司默认关闭客户端聊天同步，由该公司管理员在新增接待或客户运营中开启。客户端显示同步状态。
- WhatsApp、Telegram、LINE 尝试读取平台已加载、已缓存的私聊历史与后续消息。不主动翻页拉取历史、不发送消息、不标记已读；平台未开放的记录不可读取。
- 管理员查看只读文字记录，按账号与客户分页。媒体展示类型及可读取的文字说明，不加载外部媒体资源。
- API 号码展示系统原来已保存的消息。所有来源均不保证完整平台历史；界面区分可读取范围、未初始化和受限批次。
- 关闭同步停止后续内容上传、清除本机待上传队列；服务器已经保存的历史继续可读。
- 旧客户端不提供内容同步，需使用本次构建的新客户端；正式客户端下载版本为 0.1.13，升级不会主动清除本机账号资料。

## 存储与权限

- 新增迁移 `023_team_supervision.sql`，只增加设置、归档消息、同步元数据和查询视图，不删除或重写现有业务数据。
- 新增客户端正文在服务端使用现有主密钥 AES-GCM 加密；本机队列使用 Electron safeStorage 加密，限定公司、设备与账号。
- 客户端上传校验公司、登录码、设备、账号归属和平台本人身份。只有明确完整的服务器确认才清除待上传数据，失败保留重试。
- 后台 API 始终按当前登录公司的 tenant 过滤，消息查看写入审计记录，审计不保存消息正文。
- WhatsApp 既有 `数字@lid` 资料与 `lid:数字` 采集标识统一关联，保留原有客户备注，避免重复统计。

## 本地验证

- 客户端采集、Unicode 边界、加密队列、完整确认、关闭及损坏缓存清理有独立测试。
- 后端测试使用临时 schema，覆盖租户隔离、默认关闭、账号授权、首次接待口径、日期、去重、分页、加密、API 历史和停用后保留。
- `scripts/check-team-supervision.mjs` 配合显式启动的 `TestTeamSupervisionBrowserFixture` 验证真实本地 API、响应式界面与聊天转义；测试样本不会写入现有业务表所在 schema。
- `scripts/check-team-archive.mjs` 使用独立 Electron 数据目录和模拟平台验证采集、持久化、重试、关闭及 IPC 边界，不连接实际客户账号。

以上验证不能替代真实平台登录后的兼容性确认。平台内部缓存结构变化时，将保留现有登录与接待统计，并将无法读取的聊天范围显示为不可用。
